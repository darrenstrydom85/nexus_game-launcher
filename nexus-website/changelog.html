v0.5.3

Aug 26, 2026 · Latest

HowLongToBeat is back. HLTB moved its search API again, which silently broke completion-time lookups for every game — the third move this year. Nexus now follows the new endpoint and, if HLTB moves it again, finds the new path on its own at runtime instead of waiting for an app update.

Fixed

  • HowLongToBeat lookups — Automatic and manual HLTB searches work again after the site relocated its search API.
  • Self-healing HLTB client — When HLTB moves the endpoint, Nexus re-discovers the path from the site itself, so future rotations shouldn't need a release.

Aug 3, 2026

A quick patch for Retro Mode's ANSI cover art. Production builds were blocking the dither pipeline's image loading, so covers showed a NO SIGNAL card instead of art — dev builds were unaffected, which is how it slipped through. Covers now render correctly in the released app.

Fixed

  • ANSI cover art — The dithered cover pipeline now loads images correctly in production builds; covers no longer fall back to NO SIGNAL.

v0.5.1

Aug 3, 2026

Nexus goes retro. Flip the new Retro Mode switch and your library becomes a DOS-era terminal — complete with a BIOS boot sequence, CRT scanlines, ANSI-dithered cover art, and PC-speaker beeps. Everything runs from the keyboard: stats, play queue, collections, a random picker, and a WRAPPED.EXE year-in-review slideshow.

  • Full DOS-style retro mode with BIOS boot, CRT effects & PC-speaker audio
  • ANSI-dithered cover art, starfield & matrix-rain screensavers, Konami surprise
  • WRAPPED.EXE year-in-review plus keyboard-driven stats, queue & random picker

New

  • Retro Mode — A full DOS-era interface for your library, with a prominent switch in the modern UI to jump between the two. Complete with retro-styled toasts, session note prompts, and an authentic BIOS boot with the NEXUS ASCII logo, boot chime, and floppy-seek sounds.
  • CRT vibe pack — Scanlines, screen effects, and screensavers (starfield and matrix rain), plus a shutdown screen when you leave retro mode.
  • ANSI cover art — Game covers rendered as ANSI-dithered terminal art in the detail view, with a SETUP toggle.
  • Keyboard everything — F1 help, F4 collections filter, F6 stats & player progress, F7 play queue, F10 random picker, E edit title, R refetch metadata, M IGDB search.
  • WRAPPED.EXE — A year-in-review slideshow of your play history, retro style.
  • Abort, Retry, Fail? — Launch errors get the classic DOS prompt, and a certain 30-lives code triggers fireworks.

Improved

  • Update prompts in retro — In-app update notifications now appear inside retro mode too, and your chosen view persists between sessions.
  • PC-speaker audio — Key beeps and boot sounds are on by default, with readable ON/OFF states in retro setup.

v0.4.3

Jun 18, 2026

Nexus now updates itself. When a new version is released, the app checks on launch, downloads the new build in the background, and installs it on the next restart — so you stay current without hunting down an installer. Releases are cryptographically signed and verified before they're applied.

  • Automatic in-app updates with background download & install
  • Signed releases verified before installation
  • Update prompt on launch and a refreshed known-issues feed

New

  • Automatic updates — Nexus detects new versions and downloads + installs them in the background, applying on restart. No more manually downloading each release.
  • Signed & verified — Every update is cryptographically signed; the app verifies the signature before installing.

Improved

  • Update notifications — A prompt on launch (and an hourly check while running) lets you know the moment a new version is available.
  • Known issues — The in-app known-issues list now updates independently of app releases.

v0.3.6

May 2, 2026

A maintenance release focused on keeping the lights on. HowLongToBeat's internal API was rotated again and broke search inside Nexus — the client has been pointed at their new endpoint. The Wrapped “Your #1 Game” screen gets a richer layout with the game’s banner, cover, and logo. Under the hood, five RUSTSEC certificate-validation and networking advisories have been patched.

  • HowLongToBeat search works again
  • Richer “Your #1 Game” Wrapped card
  • Certificate-validation and QUIC DoS patches

Fixed

  • HowLongToBeat search restored — HowLongToBeat rotated their internal API path again; auto-fetch and manual search started returning a “Search failed — HLTB may be temporarily unavailable.” error. Nexus now points at the current endpoint with the same three-part authentication scheme and resumes normal HLTB lookups without any action from you.

Improved

  • “Your #1 Game” Wrapped card redesign — The full-bleed background now uses the game’s landscape banner (with a fallback to cover art), and the title area shows a prominent portrait cover plus the game’s logo. When no logo exists it falls back to the previous big-text title. Smaller Wrapped tiles still use cover art, which suits their portrait framing.

Security

  • Certificate validation patches (4 advisories) — Bumped rustls-webpki from 0.103.9 to 0.103.13 to resolve RUSTSEC-2026-0049, RUSTSEC-2026-0098, RUSTSEC-2026-0099, and RUSTSEC-2026-0104 — covering CRL authority handling, URI and wildcard name-constraint bypasses, and a panic in CRL parsing. These affect HTTPS validation for all outbound requests (IGDB, SteamGridDB, Twitch, HowLongToBeat, Google OAuth).
  • Quinn DoS patch — Bumped quinn-proto 0.11.13 to 0.11.14 to resolve RUSTSEC-2026-0037 (denial of service in Quinn endpoints, pulled in transitively via reqwest).
  • Dev toolchain hardening — Patched eight GHSA advisories across Vite, PostCSS, Picomatch, brace-expansion, Hono, and path-to-regexp. None of these packages ship in the installed app — they only run on developers’ machines during build — but this keeps the local dev server, build pipeline, and CLI tooling clean.

v0.3.5

April 29, 2026

How Long to Beat estimates now translate raw hours into real calendar time. Each metric on a game's detail page shows a ~N days figure based on a play pace you set in Settings → Library, so "45h for Completionist" becomes ~30 days at 1.5 h/day. Links in the Twitch chat sidebar also finally open — in your default system browser — instead of doing nothing.

  • HLTB "~N days" alongside each hour estimate
  • Configurable daily play pace (0.5 – 8 h/day)
  • Twitch chat links open in your default browser

New

  • Days-at-pace for HowLongToBeat — Under each HLTB metric (Main Story, Main + Extras, Completionist) the detail page now shows a muted ~N days estimate in addition to the raw hour figure. Numbers are rounded up so the day count always represents enough time to actually finish at your chosen pace.
  • Configurable daily play pace — A new Daily play time dropdown in Settings → Library → How Long to Beat lets you pick anywhere from 0.5 to 8 hours/day. The choice persists across restarts and updates every HLTB card immediately. Default is 1.5 h/day.
  • Screen-reader-friendly HLTB rows — Each metric's row announces both the hours and the day estimate together (e.g. "Main Story: 12 hours, approximately 8 days at 1.5 hours per day"), with the visual days line marked aria-hidden so assistive tech doesn't hear it twice.

Fixed

  • Twitch chat links open in your default browser — Clicking a link inside the Twitch chat sidebar of a pop-out stream (usernames, shared URLs, Twitch videos, mailto: addresses) used to do nothing — the target="_blank" request was swallowed by the embedded webview. New-window requests are now intercepted in Rust and handed off to your OS default browser via the opener plugin. Dangerous schemes (javascript:, data:, file:, and friends) are logged and dropped rather than launched.

v0.3.3

April 23, 2026

A focused reliability release for the Twitch integration. Fixes the overnight token-refresh bug that was silently signing people out, and routes Twitch clips through the same local-origin pop-out pattern the stream player already uses so they render in packaged builds.

  • Overnight Twitch token refresh
  • Clips open in an in-app pop-out

Fixed

  • Twitch integration stops working overnight — The background token-refresh worker was omitting client_secret on the refresh grant, which Twitch rejects with 400 invalid_client: missing client secret. Once the refresh failed, the stored tokens were cleared and the whole integration went dark until you signed in again. The refresh call now forwards the same client_secret the initial exchange already uses, so tokens rotate cleanly overnight.
  • Top clips refused to connect in packaged builds — Clicking a clip on a game's detail page opened an in-app modal whose clips.twitch.tv iframe was blocked by the same frame-ancestors=localhost CSP that required the stream-player pop-out. Clips now open in their own Tauri window loaded from the local embed server, matching the live-stream UX — one window per clip, draggable and resizable, native close button.

v0.3.2

April 23, 2026

A complete Twitch overhaul. The integration was rebuilt from the ground up to fix recurring token-expiry issues and to unlock a stack of features people have been asking for: a pop-out stream viewer, push-based go-live alerts, top clips for every game in your library, watch-time stats that follow your date range, a Twitch diagnostics panel, and a one-time in-app sign-in that makes every embed logged-in.

  • In-app Twitch stream viewer
  • Push go-live alerts (EventSub)
  • Top clips per library game
  • Twitch watch time in Stats & Wrapped

New

  • Watch streams without leaving Nexus — Click a live streamer anywhere — from the Twitch panel or the "Live on Twitch" section of a game's detail page — and the stream opens in its own Nexus-owned window with chat alongside it. It's a regular Windows window: drag it, resize it, minimise it, throw it on a second monitor, no always-on-top. One window per channel, and clicking the same streamer again just focuses the one that's already open. A built-in "Open on Twitch" button hands off to your default browser if you'd rather watch there.
  • Sign in to Twitch from inside the launcher — A "Sign in" button in the player chrome opens a small twitch.tv login window. Once you sign in there, every embed in Nexus is automatically logged in — chat works, the follow button works, mature-content gates auto-confirm. The session persists across restarts.
  • Push-based go-live alerts — A new EventSub WebSocket connection means you get notified the moment a streamer you follow goes live, instead of waiting for the next polling tick. Polling stays on as a 10-minute safety net.
  • Top clips on every game page — Each game in your library now shows a row of the top Twitch clips for it (last 7 days). Click a thumbnail to watch the clip in place — no second app, no browser tab.
  • Twitch watch time in Stats & Wrapped — Every stream you watch through Nexus is logged. Stats and Wrapped both follow the global date-range selector, so you can see your last 7 days, last month, last year, or any window you choose — total time, sessions, top channels, and top games.
  • Twitch diagnostics panel — A new collapsible section in Settings → Twitch shows your current token state, refresh history, EventSub connection state, rate-limit usage, and last error. There is a one-click "Test connection" button and a copy-to-clipboard button if you ever need to share diagnostics.
  • Branded HTML callback page — The Twitch sign-in flow now returns to a styled, auto-closing success page (matching the Google Drive flow) instead of a blank tab.

Improved

  • Self-healing Twitch tokens — Token management was rebuilt around a centralised, refresh-aware manager. A background worker proactively renews access tokens before they expire, so the integration stops silently breaking after a few hours. Your avatar is also fetched and cached at sign-in time.
  • Hardened OAuth callback — Both Twitch and Google Drive sign-in flows now correctly send the full HTML response on Windows before closing the local socket, fixing the blank-page issue some users hit on first connect. The Twitch flow also now validates a CSRF state parameter end-to-end.

Fixed

  • Twitch embeds render in packaged builds — Installed builds previously showed a "refused to connect" placeholder instead of the actual stream because Twitch's security policy blocks the Tauri webview origin. Nexus now hosts the embed pages from a local origin that Twitch accepts, so streams, chat, and clips all render correctly from the MSI installer.
  • Settings and onboarding work again after sign-in — An earlier embed workaround stripped a required header from internal app calls, which could leave existing users stuck on the onboarding screen or seeing "500 Internal Server Error" toasts. That workaround is gone; existing preferences and API keys are detected correctly on launch.
  • Close button works during onboarding — The close-to-tray / minimise / cancel dialog is now mounted at the top level of the app, so the title-bar close button behaves the same whether you are in onboarding or the main launcher.
  • Quieter logs — Benign "connection error (os error 10060)" entries from the browser's preconnect pool no longer spam the embed server log.
